# 用户、设备与安装统计 v2 运维说明

适用版本：Backend/Admin 本次提交；Android 1.0.6 / 38。业务时区 Asia/Shanghai（UTC+8）。

## 原因与边界
旧 canonical_users 将 PHONE 账号、未关联设备及历史 DEVICE 用户行混合成“累计用户量”；用户管理则统计 USER 行。因此截图中的 238 与 240 并非同口径。账号→user_devices→设备全部 installations 的查询也会把设备上的其他安装计到账号名下。9 次安装不能据此判定为 9 次重装或 9 次登录。
旧 current_user 在普通鉴权请求中写 APP_ACTIVE，不能用于前台活跃。Android 旧 MMKV 安装 ID 的首次读写没有并发锁；本次改为同步 AtomicFile/noBackupFilesDir 持久化。
旧历史数据缺少型号，且部分用户只有账号行，没有可靠安装关系。保留这些记录，不补造型号、不按 IP/昵称/型号合并。

## 统计定义
- activated：收到实际激活证据的 installation_id；历史成功上报保留 LEGACY_REPORT，不等于 APK 下载或人数。
- devices：激活安装中有效 device_id 去重；辅助标识仅在应用签名、Android 系统用户与设备等范围有效。不同型号、同型号均不决定身份。标识发生变化降级为 CHANGED/未识别，不自动认定新物理设备。
- registered：非已注销 USER/PHONE 账号。学校绑定、预约资料、当前登录状态不决定注册事实。
- guests：激活安装中从无可验证平台注册关联的安装记录；ever_registered 保留事实，退出登录不转成从未注册。
- unidentified：激活安装缺少有效 device_id；型号是否已上报另行表达。
- todayActive/monthActive：有效 ACTIVATE/FOREGROUND 事件按安装去重；30 天为滚动窗口，今日按 UTC+8。后台读取和版本轮询不刷新。
- todayFirst：NEW_INSTALL 且今日收到首次激活；有历史安装证据、升级补登记或首次安装时间无法确认的样本不算今日新增。
- legacy：历史 DEVICE 业务资料行，独立页签；不是游客人数，也不与安装相加。

卡片、列表、分页和导出共用查询与管理员绑定的 10 分钟快照；资料变更、撤回和删除使快照失效。失效需刷新。测试安装 is_test 排除。已删除历史汇总不伪造明细。

## 协议与权限
先通过兼容 /auth/device 建立安装身份；v2 installationSecret 存散列。安装事件要求该凭证，账号关联只来自已验证 bearer。设备键不是登录凭据，也不用于恢复已删除账号。
每安装 eventId 唯一，重复事件不重复写入；同事件编号不同类型/时间冲突 409。服务器接收时间与客户端时间分开保存，未来超过 5 分钟/延迟超过 30 天不计活跃；有效未来时间截到接收时间，乱序不降低最近活跃。
非必要统计单独同意，拒绝不阻断业务；撤回清除型号、设备关联、活跃事件和待发资料。撤回前旧事件不能恢复同意。细粒度事件保留最多 180 天，接受事件时清理；最小激活事实保留用于去重。
超级管理员可直接读取完整合法业务资料；角色路径鉴权仍在服务端。所有响应排除密码散列、密码盐、token、设备原值和安装凭证。业务编辑记录操作者、时间、字段名，不保存秘密；修改手机号检查唯一性、清空验证事实并撤销旧会话。修改预约资料清空原确认记录，要求用户重新确认。身份、原始设备事实、活跃时间不可直接编辑。

## 迁移与回滚
initialize_database 在旧 schema 初始化后执行 identity_statistics.migrate；BEGIN IMMEDIATE、增量加列、唯一约束和 identity_migrations 保证幂等。仅成功历史行为事件明确提供 installation_id 时补账号关联，不从设备范围推断。
生产备份恢复演练（2026-10-03）：242 users、99 devices、151 installations 前后不变；重复迁移、integrity_check、foreign_key_check 与重新打开恢复库通过。65 注册账号；151 激活安装；99 可识别设备；32 未识别；45 安装具备成功事件中的精确账号证据；106 安装未有注册关联；175 历史匿名资料。新前台口径初始 0，不能挪用 4383 条历史普通请求 APP_ACTIVE。
部署前使用已有一致性备份与 verify_backup；数据备份仅留受控服务器，不入 Git。新增列/表兼容旧客户端及旧服务器代码；代码回滚优先恢复上一发布，保留增量数据。生产已有新写入后不得无条件恢复旧 DB 覆盖，应停写评估并前向修复。确需全库恢复须单独确认并先备份当前库。

## 验收与限制
74 项 Python 自动测试通过，覆盖身份关联、幂等并发、旧协议、时间乱序、权限、完整业务编辑、注销/撤回、型号映射、快照、导出一致性及无流量时的事件保留期限清理。生产入口每小时执行一次保留期限清理，不依赖用户继续上报。
Android 127 项 JVM 测试通过；独立 x86_64 Debug 模拟器对本地后端完成并发身份、激活、节流、退出和撤回仪器测试。正式 APK 仍为既有 ARM64 构建，不因模拟器改正式 ABI。
后台本地合成数据验收了详情、编辑保存、设备备注、品牌筛选；1366 与 1920 宽布局检查。真实个人资料截图不入仓。
PENDING_REAL_DEVICE：正式签名 APK 在真实手机的覆盖升级、本地课表/学校凭据保留、两台同型号手机、多账号实机切换、卸载重装/清除数据及厂商迁移行为。自动化与模拟器不代替这些证据。
旧客户端仍可调用原业务接口；品牌、型号、Android 版本和可信前台活跃须升级并同意后才能补齐。历史关系缺少证据时继续显示未确认。
