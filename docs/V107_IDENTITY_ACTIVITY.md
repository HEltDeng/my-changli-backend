# V1.0.7 用户、学校绑定与活跃统计变更

本版本沿现行 1.0.6 后端增量维护。Android 1.0.7 为待用户确认候选，正式分发仍为 1.0.6/38，最低版本及普通更新规则不变。

## 证据与原因
- 旧设备列表只有设备描述，安装账号关联没有组成可识别的业务上下文；学校绑定学号原本仅存在手机本地，预约表填写的学号不能代替学校登录结果。
- V1.0.6 前台事件未保存事件时账号归属，不能依据安装曾登录的全部账号回算账号日活。
- 原统计快照逐项查询与卡片复算未共享读事务；本次以 SQLite 读事务捕获各范围，卡片、日期趋势、分页、导出使用同一个管理员专属快照。
- 旧前台节流仅使用成功发送时间，跨北京时间零点和延迟补发会吞掉当日第一次真实使用。协议 3 与客户端按事件日、版本和账号变化分别处理。
- 撤回与重新同意新增回执确认，兼容手机时钟略慢，且重试不撤销之后的新授权。

## 数据与接口
新增 school_bindings、school_binding_operations；安装增加学校结束标记，事件增加事件时账号及设备字段。学号 TEXT 按学校＋学号处理，保留前导零；冲突可见，不合并账号。
POST /api/v1/school-binding 严格字段白名单、安装凭证及平台 Bearer 校验。仅保存学校标识、学号、绑定状态、客户端校验来源、同意版本与时间。不接收学校密码、Cookie、验证码、令牌、密码哈希或完整学校响应。
解绑、撤回回执只保留操作 ID、类型和时间；撤回删除本安装学校关联。注销清除相关学校个人资料及事件账号归属。旧版协议 2 继续支持，旧事件不补造账号归属。
主要运营展示为设备日活、7 日、30 日、5 分钟活跃，账号活跃另列。近 30 日与自然月分别计算。缺少协议 3 的历史账号趋势标为缺数据。可识别设备与累计激活设备当前同义，合并展示。未识别活跃安装在覆盖说明中单列。

## 管理界面
按学号、平台昵称/编号、设备型号显示主识别；详情保留当前、历史、已解绑与冲突。搜索、导出包含学校绑定和关联账号。管理员权限沿现有服务端校验；完整业务资料仅向超级管理员开放，密码和令牌不返回。

## 迁移及恢复
2026-10-03 一致性备份已在服务器受控目录恢复到隔离数据库，迁移重复执行，integrity_check=ok，foreign_key_check=0。用户 245、设备 100、安装 154，迁移前后不变；学校绑定 0，不静默补填。
备份及生产明细仅在受控输出/服务器保存，不进 Git。增量表列保持向后兼容，可回滚旧代码继续业务；新数据保留供前向修复，禁止删除表来回滚。

## 验证
后端完整自动化及并发快照、学校权限/冲突、事件归属、回执重试测试见本次测试日志。浏览器使用独立合成数据验证列表、完整学号搜索、关联详情、下钻与导出。真实学校登录与真实手机密码管理器仍须实际设备验收；不能把模拟测试写成真实学校验证。
