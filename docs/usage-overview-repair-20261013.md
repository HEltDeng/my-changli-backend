## 现场结论

生产来源核验：修复前 Backend/Admin 为 `b8fab58c0226f48bc571732aa67984456bc94571`，与当前 `codex/campus-activities-preview` 分支一致，不以旧来源文档中的 main 当作生产版本。

2026-10-13 上午只读核验：平台注册账号 66；近七个北京时间日有 42 个匿名安装身份、4 个平台注册账号成功认证。原前台口径的设备周活、账号周活均为 0。服务 active、数据库 quick_check 为 ok；所检查日志无 Traceback 或 CRITICAL。

`/auth/device` 也记录 `LOGIN_SUCCESS`，但它是匿名安装服务认证，不代表平台注册账号登录，也不证明一个独立学生。原概览只读 `installation_events`，遗漏已有成功账号登录及业务使用。新注册及登录指标虽有旧接口字段，概览没有显示。

型号缺失的客户端原因：正式 V1.0.7 源码的 `AUTOMATIC_SYNC_POLICY_ENABLED=false`，欢迎页确认不启用此前未决定的可选统计；数据授权管理只有撤回入口。15 个记录 V1.0.7 的安装中，仅 1 个具有型号。不能把升级成功等同于设备资料上报成功，也不能推断所有未上报用户都拒绝过授权。

## 新口径

- 后端使用安装：有明确安装标识的成功 APP 来源认证或业务事件，按安装去重。纳入 SERVICE_ONLY 安装，但不把它伪造成已激活设备。
- 平台账号活跃：成功注册、登录、白名单业务操作，以及事件发生时可验证账号的前台事件，按 PHONE 账号去重。
- 今日成功登录账号：当日成功登录的平台注册账号去重；注册返回登录态也计入，不是“第一次使用 App”的人数。
- 新注册：账号创建时间按北京时间日筛选；显示今日、近 7 日和累计。
- 授权前台设备：保留原 ACTIVATE/FOREGROUND 设备口径。安装服务认证不补造前台事件、型号或物理设备身份。

排除失败、管理员操作、旧 APP_ACTIVE 后台鉴权记录、测试安装、注销账号；时间上限采用快照 asOf。无安装标识的业务事件可计入明确账号的使用，不能反推具体安装。实际 App 使用仍可能发生在本地或学校服务，以上均为后端可观测范围，不是全量人数。

所有卡片、趋势柱、明细、分页与导出共用管理员绑定的统计快照。保留前台时间字段，新增后端使用/平台注册账号登录时间，不改写历史记录。行为表新增身份筛选与中文事件说明。
